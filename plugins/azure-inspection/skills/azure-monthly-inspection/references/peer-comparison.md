# 同类资源对比：找根本原因，对齐标准做法

发现一个资源有问题时，不只给出绕过问题的办法，而是与同类资源对比：它哪项配置或创建方式和别的不一样？客户自己已经在用的标准做法是什么？

## 为什么要做

举例：一台生产数据库没有开启区域冗余高可用，也没有异地备份。只看这一台，建议会是“开启高可用”，但不知道为什么会这样，同类问题下个月还会出现。

和同类数据库对比后发现：其他生产库都由客户的 IaC 模块创建，模块默认开启高可用和异地备份；只有这一台是在门户手工创建的，用了门户的默认值。

所以建议要写成：
- **根治**：按客户自己的模块重新创建或修改这台数据库，与其他生产库保持一致；以后新建统一走模块。
- **短期**：先在门户开启高可用和异地备份（可原地修改，需要维护窗口）。

## 怎么做

1. **确定同类资源**：同一资源类型、同一用途（例如“生产 AKS 主集群”“生产 MySQL”），必要时按业务线或区域分组。供应商创建的资源（`customer.yaml` 的 `vendorManaged`）单独成组。
2. **确定标准做法**：
   - 优先用客户自己已在使用的良好做法，即多数同类资源的配置，或用 IaC 模块创建的资源的配置（`standardDeploymentTag`）。
   - 没有内部范例，或多数都不合理时，参照 Microsoft 推荐做法，并说明来源。
3. **列出偏差**：问题资源哪些属性和标准不同，每项写“当前值（同类标准：xx）”。
4. **找原因**，从以下几方面找证据：
   - **创建方式**：门户向导、IaC、脚本。看部署历史和标签，资源组部署记录可保留较久，不受活动日志 90 天限制。
   - **创建时间**：ARM 的 `createdTime`，是否早于标准模块出现。
   - **业务线和团队**。
   - **是否由供应商创建**。
   - **模块默认值**：模块默认值本身有问题时，同一模块创建的资源会一起出问题。
5. **给出对齐建议**：
   - 每项偏差说明能否原地修改，还是需要重建或迁移。
   - 需要重建的，给出短期缓解措施。
   - 如果是模板默认值的问题，建议同时修正模板，避免新资源再出现同样问题。

## 报告中的体现

- Excel 问题清单有三列：“与同类资源的差异”“根本原因”“对齐标准的做法”。
- 05 同类资源配置对比报告单独汇总，内容包括：
  - 各资源类型的标准做法
  - 偏差最多的创建方式和业务线
  - 需要修正的模板默认值
  - 所有资源都没做到的“共同缺口”
- 汇总报告用一节说明规律，例如“多数问题出在没有按标准方式创建的资源上”。

## 写法要求

- 用直白的数量表达：“40 个中有 10 个（25%）”，不用分数或比例符号。
- 原因要有证据。推断的原因写“可能”，并写明证据，例如“部署记录显示由门户向导创建”。
- 不点名个人；团队或业务线可以写。
