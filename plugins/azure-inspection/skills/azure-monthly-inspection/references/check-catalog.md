# 检查项目录（可靠性、安全、卓越运营、性能效率）

成本巡检的内容见 `cost-review.md`。本文件列出四个 WAF 支柱的检查项：看什么、从哪里读、什么情况算问题、默认严重程度。

**设计原则：把“会出问题的条件”变成每月可以读取的数字或配置。**例如 AKS 子网 IP 用尽，不等扩容失败才发现，而是每月看“剩余 IP 是否够每个节点池扩到上限，再加上升级时临时多建的节点”。

## 严重程度

| 等级 | 含义 |
|---|---|
| 高 | 可能直接导致故障、数据丢失或被入侵；或用户已经受到影响 |
| 中 | 单点故障、缺少必要防护、监控覆盖缺口、接近容量上限 |
| 低 | 建议改进，短期没有直接风险 |

生产资源按默认等级；测试和开发资源一般降一级。有外部证据改变判断时可以调整等级，例如客户提供证据表明问题资源只用于内部测试并已计划下线。调整须在说明文件里写明理由（见 `narrative-format.md`）。

## 状态标记

- **已实现**：已有脚本实现，并在实际巡检中验证过结果，随月度流程自动检查。
- **已实现（APRL）**：来自 APRL 白名单查询（`scripts/azinspect/waf/aprl/rules.py`），说明和严重程度按本目录重新定级，问题文字里标注 APRL 编号。
- **待补**：同一检查项中尚未自动检查的部分。

除上表外，O2 告警检查另与 AMBA 推荐告警对比（只报“有部分告警但缺核心告警”的生产资源），04 的 Excel 附“推荐告警（AMBA）”页；03 另有“Landing Zone 对照”一节（不计入问题数）；01 的“当前闲置资源待确认”并入孤立资源查询。

## 需要客户补充才能检查的内容

以下内容只读账号无法读取，列入“需要客户确认”：

- AKS 集群内部配置：副本数、PodDisruptionBudget、健康检查、资源请求。需要集群只读访问；本 skill 不取集群凭据。
- 应急预案和恢复演练记录。
- 业务恢复目标（RTO/RPO）、数据重要性、哪些虚拟机存有不可重建的数据。
- RI/SP 订单（需要计费账户读取权限）。
