# Azure 月度巡检插件（只读）

用客户提供的只读账号读取 Azure 配置、指标和费用，生成给客户的中文巡检报告：

| 编号 | 报告 |
|---|---|
| 00 | 汇总报告 |
| 01 | 月度成本巡检 |
| 02 | 虚拟机利用率与规格优化 |
| 03 | 可靠性与安全巡检 |
| 04 | 卓越运营与性能效率巡检 |
| 05 | 同类资源配置对比 |

全部检查只读。脚本只允许读取，会拦截写操作和取密钥；令牌必须属于客户配置里的只读账号，否则停止。不会切换你的 Azure CLI 默认账号。

> **使用前请注意**：本插件尽量保证巡检结果准确，但报告里的问题、建议和预计节省，都是根据读取到的配置、指标和账单数据自动分析得出的，可能因为数据不完整、权限不足、环境推断（例如按名称判断是否为生产环境）或规则本身的局限而出错。报告中的任何改进项，都需要由熟悉该环境的负责人逐项审阅、确认影响并按变更流程批准后再执行；请不要不经审阅就直接照着报告修改生产环境，尤其是删除资源、降配、调整网络和权限这类操作。报告中标注“需要客户确认”的内容，务必先确认再处理。使用本插件产生的任何变更及其后果，由执行变更的一方负责。

> **当前版本 0.10.10**：全部 6 份报告（00 汇总、01 月度成本、02 虚拟机规格、03 可靠性与安全、04 卓越运营与性能效率、05 同类资源配置对比），01–05 可按客户选择只做一部分（`customer.yaml` 的 `report.include`，00 只汇总所选），也可只查客户指定的订阅，并入 APRL、Defender/Policy、孤立资源、AMBA、Landing Zone 清单等微软公开规则库；RI/SP 覆盖、使用率和购买建议；跨报告交叉核对、质量检查和打包。跨月跟踪（自动与上月比：新增、已解决、仍未处理）按资源判断；读取失败、不在本月范围或范围不完整的问题记为“本月未检查”并写明原因，不算作已解决。进度见 SKILL.md 文末。

> **0.10.10 修复**（来自 0.10.9 正式版的大租户在线采集）：
> - 单次读取设总时长上限（每次尝试最多 10 分钟）：服务端一直很慢地回数据时，原来的网络超时不起作用，一次活动日志读取能卡住近 6 小时；失败操作检查（R12）到 30 分钟限时会中断正在进行的读取，已读的保留。进度输出出错时不再停止输出。
> - R12 按真实原因写：订阅的活动日志读取失败（如无权限）不再写成“记录太多”；限时内一条也没读到的写“没有读到任何记录（请求长时间没有返回）”；“只读到约 N 小时”截止到开始读取的时刻（以前采集拖到第二天时会多算）。用旧数据重新分析也会改正。
> - R5：已停止的 MySQL/PostgreSQL 不再报“高可用状态为 ，当前不能保证故障切换”（高）；停止的服务器由 R11 报告。

> **0.10.9 修复**：
> - 性能效率采集更轻：不再读取没有任何检查使用的指标（规模集逐台 CPU/内存、AKS 逐节点、AI 令牌/PTU/调用次数、负载均衡逐后端 IP）。这些读取在大租户上常被限流，让 P1、P9 显示“部分读取失败”；用旧数据重新分析时也不再计入。
> - AKS 节点状况整份读取被指标后端限流时，改为只读 Ready 条件：节点就绪情况照常检查，检查覆盖写明内存、磁盘、进程数压力未检查。
> - 说明文件的 checkNotes 写了“读取失败”而本月该检查没有读取失败时，build 提醒改写；检查项本月没有问题、也没有需要说明的读取情况时，不再显示说明文件里的旧说明，build 提醒删除。
> - **分页读不完不再当成读完**：一次查询翻到页数上限还没读完时，记为读取失败，检查覆盖写明“只读到最近的一部分”，跨月跟踪按“本月未检查”。以前的版本（含 0.10.8）活动日志在大订阅上可能只读到最近几天，失败操作（R12）会漏报，用旧数据重新分析时也会补上这条提醒。
> - 可靠性的活动日志（R12）按两天一段同时读取（只用 ge/le），从最近的日期往前读；某一段翻到页数上限时保留已读的部分，从读到的最早一条之前接着读（实在推进不了再对半分开）。活动日志接口不能只取失败事件，事件很多的订阅要把整月事件翻完（实测一个大订阅超过 10 小时），所以**每个订阅最多读 30 分钟**：到时停下，已读的保留，检查覆盖写明 30 天里只读到约多少小时、是哪些时段，跨月跟踪记为“本月未检查”；读取期间每 10 分钟输出进度；P5 缓存问题的资源类型统一，04 汇总表不再把同一个缓存算两次。
> - AKS 节点系统镜像不自动更新统一写成“不自动更新”；离线分析日志写价格实际读取的日期。
> - 交叉核对 X4、X5 按名称和资源类型一起匹配（同名的 PostgreSQL 和 Redis、同名的 NSG 和负载均衡不再被当成同一个资源）；01 日志表的来源查询失败时写“来源查询失败”；质量检查不再把“缓存命中率”当成内部用语；“后端池没有目标的应用网关”注明可能仍有监听在用、需要确认用途。
> - 支持日历加入 MySQL 8.4 LTS；R12“子网 IP 不足导致失败”这一条的问题编号不再随各节点池的失败次数变化（本版起固定，说明文件引用的旧编号需要改一次）。
> - 费用和预测的补读轮写出轮数、等待和用时（预测补读另存 `forecast-retry.json`），调用记录里单次调用看不出这段等待。
> - 本月没有费用的订阅不再读取下月预测（01 写“本月无费用，未读取预测”），预测补读更快；预测接口没有返回预测行的，不再写成“读取失败”；补读超过 10 分钟时输出进度。
> - **02 按实际运行小时计价**：以前每台运行机器都按每月 730 小时算，自动扩缩的 AKS 节点只运行了一部分时间也按整月算，按需费用和 RI/SP 节省都会偏高。现在按观察窗口内实际运行的比例折算每台机器的月小时数（整周运行、只缺少量样本或没有样本的仍按 730 小时）；RI/SP 是整月承诺，汇总时只对承诺比按需便宜的机器计入，其余仍按需，并写明有几台。降配节省也按实际小时算。
> - **交叉核对后暂不调整的机器不再计入 02 建议**：`narrative/02.json` 的 `crossCheckNotes` 某条加上 `"keep": true`，重新运行 analyze 后这些机器改为“暂不调整：结合其他检查结果保持原规格”，不计入建议台数和节省（同池其他节点也不再整池调整）；写了 keep 但没有重新 analyze 时，build 会提醒；analyze 会按条写出每条 keep 让多少台机器暂不调整、每月少计多少（前缀写宽时一眼能看出）。
> - **02 和 00 并排写出 Azure 自己的 RI/SP 购买建议**：02 按最近 7 天估算，自动扩缩的节点池台数每周会变，7 天可能代表不了整月，RI/SP 节省可能偏高。现在 02 在方案表下列出 Azure 按过去 30 天实际用量和客户价格给出的虚拟机预留、计算节省计划的建议数量和金额，以及 02 中只算 RI/SP（不含降配）的节省，便于对照；00 第 1 节改写 Azure 建议的 1 年期虚拟机预留金额，不再写 02 按列表价估算的 RI 节省。02 的 RI/SP 方案不再把巡检月一半以上费用已由 RI/SP 覆盖的机器和 Spot 机器算进去（它们仍按按需计算），并写明台数（来自 01 读取的购买建议），00 也写一句，并说明购买 RI/SP 的数量以 Azure 的建议为准；没有做 01 时提示去门户查看。

## 安装

skill 本身是一个自包含的文件夹：`plugins/azure-inspection/skills/azure-monthly-inspection/`。它遵循公开的 [Agent Skills 规范](https://agentskills.io)，Claude Code、GitHub Copilot、OpenAI Codex 都能使用。

### Claude Code（终端、Claude Desktop 的 Code 页签、VS Code 扩展）

把本仓库作为插件市场添加，然后安装：

```bash
claude plugin marketplace add <仓库地址或本地路径>
```

```bash
claude plugin install azure-inspection@azure-inspection
```

在会话里输入 `/azure-inspection:azure-monthly-inspection`，或直接说“给某客户做月度巡检”。仓库更新后执行 `claude plugin marketplace update azure-inspection` 获取新版本。

非交互运行（`claude -p`）时，同样建议限定工具，并停用 MCP 服务器，例如：

```
claude -p "<任务说明>" --strict-mcp-config --allowedTools "Skill Read Glob Grep Write Edit Bash(python:*)" --disallowedTools "Bash(az:*) Bash(curl:*) WebFetch WebSearch"
```

从 Claude Desktop 的会话里调用终端版 `claude` 时，先清掉继承的 `CLAUDE*`、`ANTHROPIC*` 环境变量，否则会提示未登录。

### GitHub Copilot（Copilot CLI、VS Code/Visual Studio/JetBrains 的 agent 模式）

把 skill 文件夹复制或链接到以下任一位置：
- 个人目录：`~/.copilot/skills/`
- 项目内：`.github/skills/` 或 `.agents/skills/`

Copilot CLI 中执行 `/skills reload` 后，用 `/azure-monthly-inspection` 调用。

非交互运行（`copilot -p`）时，建议只放行 python 和读文件命令，禁止 Copilot 直接调用 Azure CLI 等工具，例如：

```
copilot -p "<任务说明>" --no-ask-user --allow-tool "shell(python)" --allow-tool "shell(python:*)" --allow-tool write --deny-tool "shell(az)" --deny-tool "shell(az:*)" --deny-tool "shell(curl)" --deny-tool "shell(Invoke-RestMethod)" --deny-tool "shell(Invoke-WebRequest)" --deny-tool "shell(pwsh)" --deny-tool "shell(powershell)" --deny-tool "shell(Remove-Item)"
```

如果 Copilot 配置了能操作 Azure 的 MCP 服务器，巡检时先停用它（`--disable-builtin-mcps --disable-mcp-server <名称>`；插件要用 `copilot plugin disable <插件>`，用完再 `enable`）；账号最好只有只读角色（`access-check` 会提示可写角色）。

注意：`shell(python:*)` 放行的是任意 Python 代码，不是沙箱；只读由脚本自身的检查和只读账号保证。

### OpenAI Codex（CLI、IDE 扩展、Codex 应用）

把 skill 文件夹复制或链接到以下任一位置：
- 个人目录：`~/.agents/skills/`
- 项目内：`.agents/skills/`

重启 Codex 后，用 `$azure-monthly-inspection` 调用，或直接描述任务。

在 Windows 上运行 Codex CLI 有两个前提，否则一条命令都执行不了：
- 沙箱设为 `windows.sandbox="unelevated"`（写在 `~/.codex/config.toml`，或每次用 `-c` 指定）；
- 使用 python.org 或 uv 安装的 Python，不能用 Microsoft Store 版的 Python 和 PowerShell。

沙箱里不能用 Excel 复算公式，报告会退回结构核对。非交互运行的参考命令：

```
codex exec -s workspace-write -c windows.sandbox="unelevated" -c mcp_servers.<名称>.enabled=false "<任务说明>"
```

## 使用流程

1. 对 agent 说：“给 <客户> 做 Azure 月度巡检”。
2. agent 会依次：
   - 检查环境
   - 在你指定的目录建客户工作目录
   - 向你要租户、只读账号和订阅信息，填写 `customer.yaml`
   - 请你用只读账号登录
   - 核对能读取哪些订阅
3. 月度巡检：采集（collect）、分析（analyze）、撰写说明（agent 写 narrative）、生成并核对（build）、质量检查（quality-check）。之后交叉核对（crosscheck）和打包（package）。全部可用。

### 只做部分报告或部分订阅

01–05 可以按客户需要只做一部分，00 汇总报告总是生成，只汇总所选报告；也可以只查客户指定的关键订阅。对 agent 说就行，例如：

- “这个客户以后只做 03、04、05”
- “只做可靠性巡检”（03 只做可靠性部分，报告为 `03_可靠性巡检报告`）
- “这个月只做 01 和 03，做完改回全部”
- “只巡检 pay-prod 和 shop-prod 两个订阅”

agent 会先复述要做哪几份报告、查哪些订阅，请你确认，再改客户工作目录里 `customer.yaml` 的这两项（也可以自己改）：

```yaml
scope:
  includeSubscriptions: ['pay-prod', 'shop-prod']   # 不写或为空等于全部；支持 * 通配或订阅 ID
report:
  include: ['01', '03']                             # 不写等于全部；03/04 也可写支柱名，如 ['可靠性', '性能效率']
```

- 这是长期设置，之后每个月都按它执行；只想某个月例外，做完要改回。
- 报告文件保留原来的编号（例如只做 01 和 03 时，交付的是 00、01、03 三份），00 汇总报告里的附件按所选顺序编为附件一、二……
- 只选一部分时，采集会自动补上所选报告要用的数据（例如只选 02 时只读 RI/SP 覆盖，不做费用巡检）。没选的报告在交叉核对中显示“不适用”，打包时不包含。
- 只查部分订阅时，报告写明“按贵司选择，本次只检查 N 个订阅”；Entra ID 账号与凭据、管理组、预留和节省计划订单不按订阅划分，仍按全租户检查。跨月跟踪不会把没检查的订阅里的问题算作“已解决”。依赖其他订阅资源的检查（例如专线网关连接的专线线路常在另一个订阅）在报告里写明可能漏报，跨月跟踪记为“本月未检查（范围不完整）”；维护配置、备份、活动日志告警建在其他订阅时可能多报，报告里也会写明。订阅少，采集也快很多。

客户数据（`customer.yaml`、原始数据、报告）都放在客户工作目录，不要提交到本仓库。
